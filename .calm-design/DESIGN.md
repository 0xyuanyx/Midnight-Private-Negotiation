## 0. Brand Philosophy

### Core Values

1. **Privacy boundary** — 비공개 값·협상 내용과 공개 결과를 화면 구조에서도 섞지 않는다.
2. **Literal truth** — 실제 역할과 프로토콜 용어만 쓰며 장식용 서사를 만들지 않는다.
3. **Presentation clarity** — 멀리서 보는 청중이 세 역할의 진행 순서를 즉시 읽을 수 있어야 한다.

### Tone of Voice

짧고 기술적으로 정확한 한국어 문장을 사용한다. `Buyer`, `Seller`, `Observer`, `commitment`, `OPEN`, `AUTHORIZED`, `SETTLED`처럼 화면 이해에 필요한 역할명·공개 상태만 영어로 유지한다. `createDeal`, `joinDeal` 같은 계약 내부 동작은 화면에 표시하지 않는다. 홍보 문구, 감탄형 카피, 가짜 통계는 쓰지 않는다.

### Design Principles

1. 세 역할은 같은 크기와 같은 시각적 무게를 가진다.
2. 브랜드 컬러와 의미색은 작은 상태점·커서·로그 텍스트에만 사용한다.
3. 정보의 위계는 색보다 여백, 굵기, 명도로 만든다.
4. 터미널의 형태를 빌리되 운영체제 장식은 흉내 내지 않는다.

### Philosophy → Design Mapping

| 철학 | 디자인 결정 |
|---|---|
| Privacy boundary | Buyer·Seller·Observer를 물리적으로 분리된 3개 패널로 표시 |
| Literal truth | 헤더와 로그에 실제 역할명·프로토콜 용어만 사용 |
| Presentation clarity | 큰 모노스페이스 로그, 짧은 줄, 고정된 시간·단계 열 |

## 1. Visual Theme & Atmosphere

Midnight 공식 사이트의 어두운 바탕과 선명한 블루를 가져오되, 마케팅 페이지가 아닌 발표용 콘솔로 재구성한다. 검은 무대 위에 세 개의 작업 영역이 조용히 놓인 느낌이며, 카드 대시보드나 블록 탐색기처럼 보이지 않아야 한다.

`#0000FE`의 높은 채도는 사용자 지시에 따른 브랜드 예외다. 넓은 면적, 패널 배경, 그래디언트, 글로우에는 사용하지 않는다. 역할 구분색은 `BUYER`와 `SELLER` 헤더 텍스트에만 적용하고 Observer는 흰색을 유지한다. 로그에서는 문장 전체가 아니라 의미 토큰에만 색을 적용한다. `OPEN`, `AUTHORIZED`, 증명은 Protocol, `비공개 상태`·`비공개 협상`·`금액 비공개`는 Private, `결렬`·`CANCELLED`는 Danger, `합의`·`SETTLED`와 최종 공개 금액은 Success로 표시한다.

## 3. Typography Rules

- 한국어 UI: `Pretendard, system-ui, sans-serif`
- 영문 역할명: `Outfit, Pretendard, system-ui, sans-serif`
- 로그: `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`
- 헤더 제목: 15–17px, 600, 과도한 대문자 자간 금지
- 패널명: 12–13px, 600, 짧은 uppercase 허용
- 로그: 데스크톱 15–17px, `line-height: 1.7`, `font-variant-numeric: tabular-nums`
- 한국어가 포함되면 `word-break: keep-all`과 `overflow-wrap: break-word` 적용

## 4. Component Stylings

**Page Header**

- Default: 높이 56px, `#101010`, 하단 1px `#343434`
- 내용: 왼쪽에 공식 `Midnight-RGB_Logo-Horizontal-White.svg`, 구분선, `비공개 협상 데모`
- 공식 로고는 가로세로 비율을 유지하고 높이 약 24px로 표시하며 CSS로 재조립하거나 텍스트로 대체하지 않는다.
- Hover/Focus/Active/Disabled/Loading: 인터랙션이 없는 정적 헤더이므로 적용하지 않는다.

**Product Code Input**

- Buyer와 Seller 터미널 로그의 마지막 줄에 일시적인 프롬프트로 배치한다. Observer에는 입력이 없다.
- 페이지 로드 직후에는 렌더링하지 않는다. Demo Controller가 Buyer·Seller·Observer의 `RUNTIME_READY`를 모두 확인한 뒤 두 패널에 동시에 표시한다.
- 라벨 `상품 코드`, 형식은 네 자리 숫자, 샘플 값은 `4821`
- `[HH:mm:ss] 상품 코드를 입력해 주세요.` 아래 `> 4821` 형식이며 Enter로 방에 입장한다.
- Enter 후 프롬프트와 입력값은 로그에서 사라지고, 패널 상단 고정 상태 줄이 `4821 · 구매자 최대 한도` 또는 `4821 · 판매자 최소 금액`으로 전환된다.
- 추가 카드, 설명, 제출 버튼은 만들지 않는다.

**Terminal Panel**

- Default: `#151515`, 1px `#343434`, 6px radius, 그림자 없음
- Header: 높이 42px, 역할명과 작은 연결점 자리만 표시
- Body: 20–24px 내부 여백, 로그는 좌측 정렬
- Pre-start: 페이지와 패널 외곽만 표시하고 입력·상태 문구·샘플 로그는 표시하지 않는다. 상태점은 비활성 회색이다.
- Ready for input: 세 런타임이 준비되면 Buyer·Seller 상품 코드 입력과 Observer의 공개 상태 대기 행을 표시한다.
- Hover/Focus/Active/Disabled/Loading: 정적 프레젠테이션 패널이므로 적용하지 않는다.

**Private Limit Input**

- Buyer와 Seller 터미널의 마지막 줄에서 각각 `구매자 최대 한도를 입력해 주세요.`, `판매자 최소 금액을 입력해 주세요.`로 요청한다.
- 입력 프롬프트는 `> 금액` 형식이며 상단 고정 상태 줄은 입력이 끝날 때까지 빈 금액 자리를 유지한다.
- Default: 투명 배경, 하단 1px `#343434`, 값은 `#FFFFFF`
- Hover: 경계만 `#A8A8A8`로 높이고 배경색은 바꾸지 않는다.
- Focus: 2px `#0000FE` 외곽선과 충분한 offset을 사용한다.
- Active: 선택된 숫자와 캐럿만 명확히 표시한다.
- Disabled: 텍스트 `#A8A8A8`, opacity 0.55, 비활성 속성을 함께 사용한다.
- Loading: 저장 중에는 필드를 비활성화하되 별도 스피너나 임시 문구를 추가하지 않는다.
- 제출 버튼, 연결 상태, 도움말 카드는 두지 않는다.
- Enter 후 프롬프트와 입력한 줄을 제거한다. 역할별 로컬 비공개 상태에 저장되면 상단 고정 상태 줄에 자물쇠와 포맷된 자기 값만 표시한다.
- Buyer 예시: `4821 · 구매자 최대 한도 🔒 110,000 KRW`
- Seller 예시: `4821 · 판매자 최소 금액 🔒 95,000 KRW`
- 협상·증명·Observer 로그에는 원래 한도 값을 다시 출력하지 않는다.

**Terminal Line**

- Default: `[HH:mm:ss] 메시지` 형식으로 시간과 메시지를 고정 정렬한다. 모든 로그가 시스템 출력이므로 출처 태그는 표시하지 않는다.
- Metadata: 시간·블록 식별자는 `#A8A8A8`
- Protocol: 프로토콜 동작·현재 단계 텍스트는 `#9A9AFF`
- Private: 입력 라벨은 `#D0B36C`
- Success: 성공·최종 상태 텍스트는 `#9FB8A3`
- Cancelled: `결렬`과 `CANCELLED` 토큰만 `#D65C5C`
- Accent: 작은 상태점·커서·포커스 외곽선만 `#0000FE`
- Error: 오류 식별자와 핵심 오류 문구만 `#D65C5C`로 표시
- Empty: Pre-start에서는 실제 빈 터미널을 유지한다. 브라우저가 샘플 로그나 타이머 이벤트를 생성하지 않는다.
- `ROLE_LOCAL`, `PARTICIPANTS`, `PUBLIC`은 라우팅 범위이며 문장 전체 색을 결정하지 않는다. 모든 본문은 기본 흰색이고 의미 토큰만 별도 색을 쓴다.
- 이미 출력된 로그 행은 삭제·교체·재정렬하지 않는다. 후속 상태는 반드시 새 타임스탬프의 새 행으로 추가한다.
- 대기 행은 그대로 남기되 같은 작업의 다음 이벤트가 도착하면 그 행의 스피너만 정지한다.

**Negotiating Status**

- Buyer와 Seller의 commitment가 모두 준비되고 서로 등록되면 Controller가 두 패널에 같은 타임스탬프로 `협상을 시작합니다.`와 스피너를 표시한다.
- 약 0.8초 뒤 `AI 에이전트가 비공개 협상을 진행하고 있습니다.`를 새 행으로 추가한다. 이 행의 스피너는 협상 완료 이벤트가 올 때까지 유지한다.
- `createDeal`, `joinDeal` 같은 계약 내부 동작은 어떤 패널에도 표시하지 않는다.
- 문구는 `AI 에이전트가 비공개 협상을 진행하고 있습니다.`로 고정하며 제안 금액, 메시지, 추론, 상대방 정보는 출력하지 않는다.
- 터미널 스피너는 작은 모노스페이스 글리프 하나만 사용하고 `#0000FE`로 표시한다.
- Default: 정지된 `⠋` 글리프와 `#9A9AFF` 상태 문구
- Hover/Focus/Active: 조작 대상이 아니므로 시각 변화 없음
- Disabled: 협상이 끝나면 기존 진행 행의 스피너만 정지하고, 완료 로그를 다음 행에 추가한다.
- Loading: `⠋ ⠙ ⠹ ⠸ ⠼ ⠴ ⠦ ⠧ ⠇ ⠏` 순환만 허용한다.

**Result Disclosure**

- 성공: 구매자·판매자 증명 완료 후에만 `합의 금액 100,000 KRW가 온체인에 기록되었습니다.`를 공개한다.
- Observer는 정산 직전에 `AUTHORIZED · 가격 커밋 등록(금액 비공개)`를 표시하고, `SETTLED`에서만 최종 금액을 붙인다.
- `AUTHORIZED` 확인 뒤 `SETTLED`를 기다리는 동안 Buyer와 Seller에는 `합의 금액을 온체인에 기록하고 있습니다.`와 스피너를 표시한다.
- 실패: `협상이 결렬되었습니다.`만 표시하고 한도·제안·합의 시도 금액을 공개하지 않는다.
- 실제 Midnight 취소 트랜잭션 확인처럼 시간이 걸리는 실패 후처리에는 `협상 결과를 온체인에 반영하고 있습니다.`와 스피너를 새 행으로 표시한다. 확인 후 스피너를 정지하고 결렬 결과를 다음 행에 추가한다.
- Observer는 전체 Tx 목록이 아니라 공개 계약 상태와 최종 결과만 표시한다.

## 5. Layout Principles

- 페이지는 `min-h-[100dvh]`, 데스크톱 발표 화면을 우선한다.
- 헤더 아래 콘텐츠는 `grid-template-columns: repeat(3, minmax(0, 1fr))`.
- 패널 간격 12–16px, 외곽 여백 20–28px.
- Buyer → Seller → Observer 순서를 고정한다.
- Buyer와 Seller의 입력은 각 패널 내부 동일한 y축 위치에 둔다.
- 세 패널은 같은 폭과 높이를 유지한다.
- 본문에 추가 카드, 사이드바, 푸터, 설명 섹션을 만들지 않는다.
- 1024px 미만은 검토용 폴백으로 단일 열 전환하되 발표 목표는 16:9 데스크톱이다.

## 6. Depth & Elevation

깊이는 면 색상과 1px 경계로만 표현한다. 그림자, inset highlight, glass blur, 네온 글로우는 사용하지 않는다. z-index는 헤더 10, 콘텐츠 1로 제한한다.

## 7. Motion & Interaction

입력은 로컬 WebSocket을 통해 데모 전용 신뢰 경계인 Demo Controller로 제출되고, Controller가 대상 역할 프로세스 IPC로 즉시 전달한다. Controller는 한도를 저장하거나 로그에 남기지 않는다. 페이지 로드만으로 입력이나 로그를 시작하지 않으며, 세 역할의 `RUNTIME_READY`가 모두 확인될 때 상품 코드 입력을 노출한다. 상대 참여·commitment 등록·협상·비공개 증명·온체인 결과 반영처럼 다음 완료 이벤트까지 기다리는 모든 작업에는 작은 터미널 스피너가 순환한다. 완료·오류 이벤트가 오면 기존 행은 유지한 채 해당 스피너만 정지하고 새 로그 행을 추가한다. `prefers-reduced-motion`에서는 스피너를 고정 글리프로 표시한다. 실시간 정제 로그의 새 행은 120ms 이내의 opacity 변화만 허용한다.

## 8. Responsive Behavior

- 데스크톱 `≥1024px`: 세 패널 수평 고정
- 태블릿·모바일 `<1024px`: 단일 열 폴백
- 전체 페이지 가로 스크롤 금지
- 가격 입력 행은 44px 이상의 조작 높이와 명시적 라벨을 유지한다.
- 터미널 본문은 긴 문자열이 패널을 넘지 않도록 `overflow-wrap:anywhere`를 적용한다.

## 9. Anti-Patterns

Project-specific bans:

- ❌ 전체 체인의 트랜잭션 탐색기처럼 보이는 목록 금지
- ❌ KPI, 그래프, 설명 카드, 단계 다이어그램 추가 금지
- ❌ `LIVE`, `Powered by`, `Privacy reimagined` 같은 장식·마케팅 문구 금지
- ❌ 신호등 모양 macOS 창 장식, 가짜 브라우저 크롬 금지
- ❌ 그라디언트, 글로우, 유리 효과, 과한 둥근 모서리 금지
- ❌ 패널 배경을 역할색·상태색으로 칠하거나 로그를 무지개처럼 표시 금지
- ❌ AI 협상의 대화, 추론, 제안 금액, 중간 판단을 Buyer·Seller·Observer 어느 패널에도 노출 금지
